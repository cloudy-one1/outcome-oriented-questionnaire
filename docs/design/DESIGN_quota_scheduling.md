## 1. 现状口径（实现依据见各括号）

| 语义 | 现状 | 代码位置 |
|---|---|---|
| 单选/下拉权重 | 每次抽样的**相对概率**，与份数无关 | `answering_v2._weighted_or_equal_choice` |
| 批量比例 | 大数收敛，单批浮动（3:1 跑 20 份仅 ~10% 批次恰好 15:5） | 离线审计实测 |
| 多选权重 | 相对频率，**不是**每份答卷的入选率（8,1,1 选 2 → 入选率 ≈97.7/51/51） | `answering_v2._weighted_multi` → `utils.weighted_sample_no_replace` |
| 零权重 | 0 = 绝不选择；矛盾配置（count 超出正权重数）校验期拒绝 | v4.2 已落地 |
| 失败/unknown | 不影响权重，也不被权重感知（统计分母 = 全部尝试） | `distribution.py`（默认关） |
| 计划配额 | 仅 `--alpha-target` 信度控制模式有（边际配额 + 按秩映射），与普通自定义比例无关 | `src/plan.py` |

## 2. 待拍板的三个口径

### 口径 A：单选配额粒度

| 方案 | 含义 | 代价 |
|---|---|---|
| **A1 总量精确配额（推荐）** | 整批**明确成功**的 N 份恰好按比例分（100 份 → 10/30/50/10 各恰好）；每份生成前看"该配额还差几份"，从**未满配额的选项**中按权重抽 | 配额记账与续传/重投联动；`--alpha-target` 的计划矩阵已有同族实现可参照 |
| A2 每批精确配额 | 每 20 份恰好 15:5。批界在翻页/浏览器重启/失败重投下如何定义是硬问题，脆 | 更高；不推荐 |
| A3 保持概率 | 现状，仅文档化 | 无 |

A1 的关键性质：配额是**消耗记账**而不是"每第 N 份强制谁"——失败与 unknown
不消耗配额（见口径 C），重投自然继续填未满的格；断点续传从历史库
`submissions` 表恢复已消耗数，与续传语义天然一致。

### 口径 B：多选语义

| 方案 | 含义 | 代价 |
|---|---|---|
| **B1 维持相对频率 + 0=硬禁止（已落地的部分即此方案的底线）** | 权重是"选 k 个时各选项的相对被抽频率"，文档写明它不等于入选率 | 无（现状） |
| B2 校准到目标入选率 | 引擎调整无放回抽样，使各选项实际入选率 ∝ 权重（夹 100% 后把差额重分配，总和恒 = k） | 需要迭代校准器（`plan.py` 的按秩映射可参照）；入选率是跨份统计量，单份只能逼近 |

### 口径 C：配额分母

| 方案 | 含义 | 代价 |
|---|---|---|
| **C1 按明确成功兑现（推荐）** | failed / unknown 不消耗配额，继续投直到各格填满 ——「有效答卷比例」语义 | 生成侧要读历史库逐份成败（`submissions` 表已在，v4.1 铺好了路） |
| C2 按尝试兑现 | 失败也消耗份额；实现最简，但失败率高的选项配额缩水，最终成功分布偏离目标 | 低 |

## 3. 已实现的组合与验收

**A1 + B1 + C1**（B2 留作后续增强单独立项）。验收状态：

1. ✅ 离线模拟：目标 10/30/50/10、总 100 份、注入 25% 失败 → 成功份额**逐项
   精确等于**配额（`tests/test_quota.py::TestEndToEndExactTally`，含
   「Σ剩余配额 = 剩余成功份数」的结构不变量 —— 这是永不卡死的保证）。
2. ✅ 断点续传：按 `submissions.final_status='success'` + `answers` 明细重建
   已消耗配额（`TestResumeRebuild`）；改过权重后续传历史消耗超出配额时夹 0
   并大声说明。
3. ✅ 互斥：`--quota` 与 `--drift-correct`、`--alpha-target` 同给退出码 2
   —— 三者都在改"这份答什么"，叠加语义不明（实现取互斥，比原提案的
   "计划优先"更干净：两套配额记账各自扣各自的账没有可定义的合并语义）。
4. ✅ 收尾报告：`[配额]` 行报整体兑现数与未填满的题（尝试上限先到必有缺口，
   不静默）。
5. ✅ Web 控制台：「🎯 配额调度」开关（默认关）→ `/api/field` → 启动时冻结
   进运行循环（`quota_mode` + 隐含 `target_success`），横幅与 `[配额]` 收尾
   报告走界面日志通道；运行中导入配置的限制（P1-3）对配额记账天然成立 ——
   账本懒初始化读的是批次快照权重。

## 4. 明确不做的

- 不做"按 IP/设备指纹打散配额"——那落在 README「不在本工具范围内」的
  规避风控一侧（`未来优化方向.md` §1 同一条红线）。
- 不在 A1 里做跨问卷的全局配额——配额生命周期 = 一个批次。
